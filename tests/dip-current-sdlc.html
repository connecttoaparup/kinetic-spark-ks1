Phase 1 — Live Today
Contextual Jira Operations & Automated Support Escalation
Handle all Jira work without leaving the code editor. Git context auto-captured on every action.
⌨️
One Single Command
/dip-ings-jira-*
Developers handle all Jira tasks right inside VS Code or the terminal using one simple command prefix. No browser context switching. No copy-pasting ticket IDs. Jira lives where the code lives.
🔗
Automatic Info Grabbing
auto-context
Every ticket comment or status update automatically captures: the current Git repository name, the active branch, and the exact timestamp. Zero manual copy-paste. Perfect audit trail on every Jira entry.
🚨
Quick Emergency Support
sre-escalate
When a critical production incident hits, one command instantly creates a connected support ticket in the WMDIP project. Skips all browser forms during high-pressure moments. Engineers stay focused on fixing, not filing.
1
Developer types Jira command in VS Code or terminal
e.g. /dip-ings-jira-comment, /dip-ings-jira-status, or /dip-ings-jira-create — no browser required. Skill activates immediately within the editor.
2
Skill auto-captures Git context
Before writing anything to Jira, the skill reads the current repo name active branch timestamp and embeds them automatically into the ticket update.
3
Jira ticket updated or created with full context
Comment posted, status changed, or new ticket created — all with traceable metadata. No missing context, no incorrect branch references.
!
Production incident path: sre-escalate
Typing sre-escalate bypasses all forms and instantly creates a linked support ticket in WMDIP project. The ticket is pre-populated with current repo, branch, and time. Incident response starts in seconds, not minutes.
Command What it does Auto-captured
/dip-ings-jira-* All Jira operations from inside the editor repo branch time

Phase 2 — Live Today
Coding & Setup Tools for Specific Projects
Domain-specific skills for every layer of the ingestion platform. Separated cleanly by concern.
Separated Workflows — Commands by Domain
Command Prefix Domain Repo Example Skills

/dip-ings-config-* Ingestion YAML Config progectai-ingestion add-job add-sql validate
/dip-ings-dag-config-* DAG JSON Config progectai-dag add-dag add-task validate
🏗️
Massive Time Saver — Onboarding
/dip-ings-dag-config-onboard
When onboarding a new data tenant, this command automatically builds every folder and basic setup file inside a blank Git repository. Developers do not create a single file or directory by hand. What used to take hours of setup is now one command.
🛡️
Smart Code Scanner — Safety Guard
/dip-ings-dag-config-validate
Automatically scans newly modified pipeline layout files for formatting mistakes before a PR can be created. Acts as an automated first-pass safety guard. Then asks for a quick human double-check for the final decision. Nothing broken ships to review.
📝
App Code Generation
/dip-write-* /dip-barricade-*
Domain-specific skills for writing PySpark tasks, services, unit tests, and GenAI application components. Each skill knows the team's code style, patterns, anti-patterns, and testing conventions — not generic boilerplate.
1
Developer identifies the task type and selects the right command prefix
App code → /dip-*  |  YAML config → /dip-ings-config-*  |  DAG JSON → /dip-ings-dag-config-*. The prefixes map exactly to domain boundaries — no ambiguity.
2
Skill reads domain context and grounded instructions
Each skill loads its copilot-instructions.md and principles files. The AI understands our exact field names, load modes, security rules (GSM, PII), and anti-patterns — not a generic LLM response.
3
AI generates the artefact — code, config, or scaffold
Output is written to the correct file path following team conventions. For onboarding: the entire folder structure is scaffolded. For config: a validated YAML or JSON is produced. For code: a tested, pattern-compliant Python module.
V
Validation scan runs before PR can open
/dip-ings-dag-config-validate scans the output for formatting errors, missing required fields, and schema violations. Must pass before a PR is created. Human confirms the final output.

Phase 3 — Live Today
GitHub Copilot Code Pull Request Support
AI-assisted PR lifecycle: grounded on private repos, auto-drafted descriptions, two-layer quality gate.
🧠
Trained on Our Code
customised instruction files
AI models are configured to read and understand our private code repositories. Customised instruction files make AI suggestions incredibly accurate for our PySpark patterns, ingestion conventions, and DAG structures — not generic suggestions from public training data.
📝
Automatic PR Descriptions
review-pr skill
The AI reads the code diff and automatically drafts a clear summary with interactive checkboxes. Developers check or uncheck boxes instead of writing long, painful summaries by hand. Reviewers get structured context immediately.
✅
Two-Layer Quality Check
Layer 1 AI → Layer 2 Human
All new code and config must pass an automated GitHub Copilot AI review (Layer 1) before being sent to team members for human review (Layer 2). Nothing reaches human reviewers that hasn't already been AI-checked.
L1
Automated AI Review (Copilot)
GitHub Copilot reviews the PR diff automatically. Checks for code quality, pattern compliance, missing tests, security issues (hardcoded secrets, missing GSM references), and alignment with our ingestion conventions. Must pass before human reviewers are notified.
Code quality Pattern check Security scan Convention check
L2
Human Review (CODEOWNERS)
After Layer 1 passes, the PR goes to designated CODEOWNERS for each domain. Reviewers see the AI-drafted description with interactive checkboxes, the Layer 1 result, and the full diff. Human approval required to merge.
CODEOWNERS review AI-drafted summary Checkbox sign-off
1
Developer pushes branch and opens PR
Branch created from story work; PR opened against main.
2
AI auto-drafts PR description with checkboxes
Copilot reads the diff and generates a structured description. What changed Why it changed Test coverage Deployment notes — all as checkable items. Developer reviews and adjusts.
L1
Automated Copilot AI review runs (Layer 1)
AI checks code quality, patterns, security, and conventions. Must pass all checks before human reviewers are pinged. If it fails, developer fixes and re-pushes — no human time wasted.
L2
CODEOWNERS human review (Layer 2)
Human reviewers see a clean, AI-summarised PR with Layer 1 results already attached. Review is faster and higher quality because the obvious issues were caught in Layer 1.
✅
Approved and merged
PR merges to main. CI pipeline runs final checks. Activity logged to the Copilot Usage Tracker (below).
